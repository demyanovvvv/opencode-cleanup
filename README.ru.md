# opencode-cleanup

[English](README.md)

TUI-плагин с англоязычным интерфейсом для просмотра хранилища OpenCode и постановки обслуживания базы данных в очередь прямо из OpenCode.

## Возможности

- Панель с данными SQLite, WAL/SHM, сессиями, историей событий, снимками, различиями сессий, выводом инструментов и памятью процессов OpenCode.
- Просмотр сессий и распределения объёма данных по типам частей сообщений.
- Отображение идентичности базы: канонического пути и сигнатуры схемы.
- Фоновое обслуживание с проверенными резервными копиями SQLite и потоковыми архивами JSONL gzip с проверкой контрольных сумм.
- Установщик, сохраняющий другие плагины и комментарии JSONC, и автономный деинсталлятор.

Экран выборочной очистки — предварительный интерфейс: полный сценарий выбора фильтров, подтверждения и выполнения пока не доступен. Команда обслуживания ставит в очередь архивирование отсоединённой истории и уплотнение базы. Перед использованием прочитайте [требования и ограничения](docs/COMPATIBILITY.md).

## Установка

Установите Node.js и OpenCode с поддержкой TUI-плагинов. Подробные требования приведены в [документе о совместимости](docs/COMPATIBILITY.md).

Скачайте ZIP из [GitHub Releases](https://github.com/demyanovvvv/opencode-cleanup/releases) и распакуйте. На Windows дважды щёлкните `install.cmd`. На других платформах выполните из распакованной папки:

```bash
node scripts/setup.mjs install
```

Также можно клонировать репозиторий и запустить установщик из исходников:

```bash
git clone https://github.com/demyanovvvv/opencode-cleanup.git
cd opencode-cleanup
npm run install:plugin
```

При установке из исходников установщик подготавливает зависимости и собирает плагин. ZIP уже содержит собранные файлы. Установщик регистрирует плагин в `tui.json` или `tui.jsonc` и выводит путь установки. После установки полностью закройте и заново запустите OpenCode.

## Использование

Откройте палитру команд сочетанием `Ctrl+P` и выберите:

| Команда | Назначение |
| --- | --- |
| `Cleanup: Dashboard` | Обзор хранилища и памяти процессов |
| `Cleanup: Sessions` | Список сессий и логический объём данных |
| `Cleanup: Analyze storage` | Типы частей сообщений и отсоединённая история событий |
| `Cleanup: Selective cleanup` | Предварительный интерфейс защиты сессий |
| `Cleanup: Database maintenance` | Архивирование и уплотнение после закрытия OpenCode |

`Ctrl+Shift+O` открывает панель. На вложенных экранах есть кнопка Back.

Размер на диске, логический объём UTF-8 и оперативная память процесса — разные показатели. Удаление записей не уменьшает файл SQLite немедленно; уплотнение выполняется отдельно. Отсоединённая история событий остаётся исходными сохранёнными данными.

Перед постановкой обслуживания в очередь проверьте показанную идентичность базы. После постановки закройте OpenCode, чтобы фоновый процесс мог продолжить работу. Сохраняйте резервные копии, архивы и отчёт задания до проверки результата.

## Настройка

Установщик учитывает `OPENCODE_CONFIG_DIR`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME` и `OPENCODE_TUI_CONFIG`. Для собственных каталогов:

```bash
node scripts/setup.mjs install --config-dir "/path/to/config" --data-dir "/path/to/data"
```

`--config <file>` задаёт файл конфигурации TUI, а `--source <directory>` — папку пакета. Путь базы берётся из `OPENCODE_DB`, если переменная задана, иначе — из пути состояния хоста. Для нестандартного хранилища предпочтителен явно заданный абсолютный путь к базе.

## Удаление

На Windows дважды щёлкните `uninstall.cmd` либо выполните из папки пакета или исходников:

```bash
node scripts/setup.mjs uninstall
```

В установленной папке плагина также находятся автономные `uninstall.cmd` и `uninstall.mjs`: исходная папка пакета для удаления не нужна.

Деинсталлятор удаляет регистрации плагина, установленные файлы, настройки и регистрации заданий. Он запрашивает отмену заданий и ожидает завершения фоновых процессов. Если процесс продолжает завершать транзакцию после тайм-аута, повторите удаление позже. **Архивы истории и резервные копии SQLite сохраняются.** Полностью перезапустите OpenCode, чтобы выгрузить плагин.

Для запуска Windows-скриптов из терминала без паузы используйте `--no-pause`.
